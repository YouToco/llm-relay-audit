# 非功能项：真伪之外要查的事（文本为主，视频适用的标了）

> SKILL.md 流程第 3、4 步。判真伪（`text-checks.md` / `video-checks.md`）回答「是不是官方模型」；这里回答「同一个模型，经它转一道后客户还拿得到同样的东西吗」。
> 每项都写了：**怎么便宜地测**、**记什么证据**、**填进 findings 哪里**（`diffs[]` 影响客户 / 接入的差异；`sections[]` 自定义节；`internal.risks[]` 只给决策人）。付费的先报价（规则 1），请求全部走 `probe_lib` 落 jsonl（规则 13），不发真实客户数据（规则 17）。
> 不是每项都要做：按用户关心的和这家的形态挑，没做的在 `method.note` 写一句。

## 1. 输出 token 虚报
- **怎么测**：同一请求（固定提示词、`temperature: 0` 能用就用、限定输出长度如「只回 50 个字」）两边各发 3 次，比 `output_tokens` / `completion_tokens` 和 `reasoning_tokens` 的分布。可见文字可用官方计数接口重数（Claude `count_tokens`、OpenAI `/v1/responses/input_tokens`、Kimi 计数接口），**但只作参考**：OpenAI 文档写明输出里有不进正文的格式 token，`output_tokens` 本来就会比可见文字多、差值随型号变（`openai.md`）；Claude 的思考 token 也看不全。真正的比较对象是**官方同请求的 usage**。
- **判据**：供应商稳定高出官方（如每单多一截、或 `reasoning_tokens` 远高于官方同题且答案一样短）= 虚报或换了更啰嗦的后端；供应商日志 `quota` 按的 token 数比它自己回包 usage 还多 = 计费层加码。
- **证据**：两边 usage 对照表（每单一行）、日志里该笔的计费 token / `quota`。
- **填哪**：`sections[]`（「输出 token 对照」表）；稳定多收写 `diffs[]`（`impact: customer`）。

## 2. 上下文窗口截断 / 封顶
- **怎么测**：「大海捞针」——一段填充文本，在开头、中间、结尾各埋一个随机码，问「三个码分别是什么」；长度取宣称上下文的约 50%、90% 两档。**先报价**：90% 档一单可能就是几十万输入 token，先用免费计数接口算好 token 数和钱，用户点头再发；先跑 50% 档，过了再跑 90%。
- **判据**：官方三码都答对、供应商丢了开头的码 = 中间层截了前文（常见于「按上下文自动裁剪」的转发层）；`input_tokens` 明显少于官方计数 = 请求被截；直接报「超过上下文」而官方不报 = 封顶比宣称小。
- **证据**：两边回答、`input_tokens`、报错原文（jsonl 引用）。
- **填哪**：`diffs[]`（`impact: customer`）；封顶数写进 `claims[]`（声称上下文 vs 实测）。

## 3. 输出被改写 / 加了审核 / 夹带内容
- **怎么测**：
  - 确定性对比：支持的厂商用 `temperature: 0`（加 `seed` 的也加上），固定提示词两边各发 3 次，逐字比；官方自身也会抖，看供应商是否落在官方的那几种输出里（`deepseek.md` 有例子）。
  - 拒答改写：挑一个官方会正常回答、但边界敏感的无害问题（如药物常识、历史战争），看供应商是否多出拒答、套话、免责声明。
  - 夹带：长回答末尾 / 流式最后几个事件里有没有广告、链接、站点名、水印字符（零宽字符也查：程序扫 `​` 等）。
- **判据**：同参数下稳定偏离官方、出现官方从不出现的拒答或附加文字 = 中间层改写或加了自己的审核 / 系统提示（结合 `text-checks.md` 注入检测一起看）。
- **证据**：两边原文并排（`exchanges[]`）、差异片段。
- **填哪**：`diffs[]`（`impact: customer`）；夹带广告 / 链接是要对方修的事，进 `asks[]`。

## 4. 数据留存与日志政策
- **怎么测**：不靠请求测——**问并记录**：对方是否存提示词 / 输出、存多久、谁能看、是否用于训练或转卖、能否签数据处理协议、日志在哪个国家 / 地区。顺便看站点公开的隐私政策 / 服务条款（记 URL 和读取日期）。供应商日志里能看到完整提示词原文本身就说明它存了（new-api 系日志 `content` 字段，见 `new-api.md`）。
- **原则**：测的时候只用自造文本，别为了「看它存不存」发真实数据。
- **证据**：对方书面答复原文、政策页 URL + 日期、日志里出现提示词的截图描述（不贴内容）。
- **填哪**：`internal.risks[]`；客户合同需要的条款写进 `internal.ask_business[]`。

## 5. 法务与服务条款风险
- **要记的事实**（只陈述事实和出处，结论交给法务）：
  - 来源是不是**消费者订阅号转卖**（sub2api / Codex 后端等，`sub2api.md`、`openai.md`）：多数厂商条款不允许把订阅转成 API 对外卖，号随时可能被停。
  - 来源是不是厂商**授权的经销 / 云平台**：问对方要授权证明或云平台账号主体。
  - 面向中国大陆提供境外模型服务，可能涉及生成式 AI 服务备案、数据出境等合规要求；反过来把境内模型卖到境外也有各自的出口与数据规定。**这里只记录「数据从哪到哪、模型由谁提供」，是否合规请咨询法务。**
- **证据**：后端判定（真伪证据里已有）、对方对来源的书面说法。
- **填哪**：`internal.risks[]`（一句事实 + 「请咨询法务」）；外发版不写评价。

## 6. 地域与延迟（从客户所在地测）
- **怎么测**：在**客户实际所在的网络 / 地区**（不是你自己的办公网）对两边各发 10 单小请求，记首字节 / 首字 / 总耗时（`call_stream()` 自带 `ttfb_ms` / `first_content_ms`）；流式和非流式配对测（`claude.md`）。顺手记供应商入口解析到哪（`dig` / 响应头里的地区字段）。
- **判据**：只报中位数和最慢一单，不写容量结论（规则 3）；首字比官方慢一个量级、或流式「首字节早、内容一次到」= 假流式 / 多层转发。
- **证据**：耗时表（jsonl 里的计时字段）、测试地点和时间。
- **填哪**：`sections[]`（「延迟」小节，`bars` 画中位数）；影响接入的写 `diffs[]`（`impact: integration`）。

## 7. 中断与失败退款（文本 + 视频）
- **怎么测**（都要先报价，按最贵情况算）：
  - 文本：流式请求在收到前几个事件后主动断开，过几分钟读日志 `quota`（`spent()`），看按实际生成量收、按 `max_tokens` 预扣全收，还是冻结额度不释放（`deepseek.md` 见过）。
  - 视频：用官方会异步判失败的参数提交一单（如 wan3 `duration` 非法、`ali-wan.md`），看终态失败后预扣有没有退回、多久退；被内容审核拒的单同理（官方不收费的情况见各厂商 reference）。
- **判据**：官方不收的它收了、或退款要人工 = 计费问题；冻结额度不释放会让客户余额「莫名变少」。
- **证据**：动作前后的日志 / 余额读数（时间戳）、对应 jsonl。
- **填哪**：`diffs[]`（`impact: customer`）+ `cost.intro` 写计费时点；要对方改的进 `asks[]`。
