# Relay supplier audit procedure (video + text lines) — English version

> English translation of `SKILL.md`; the procedure, rule numbers and scripts are the same. All other files under `references/` are in Chinese — agents can read them directly; quote them by file name and section title.
> Paths below are relative to the skill directory (the folder containing `SKILL.md`), not to this file.

**Terms**: **supplier** = the relay / proxy / reseller under test; **official** = the model vendor's own API (or the cloud platform hosting it); **user** = the person who asked you to run the audit, who is also the **decision maker** (whether to integrate is their call).
Goal: decide "is what this supplier sells the same as the official API, and is it worth integrating", and give the user evidence. **The user decides whether to integrate** (exception: a rule 16 veto means "do not integrate").
Flow: set up → free probes → quote → minimal paid matrix → verification (output files / authenticity / non-functional checks / field-by-field comparison) → fill `findings.json` → the generator renders two reports → wrap up.
Video details `references/video-checks.md`, text details `references/text-checks.md`, non-functional checks `references/nonfunctional-checks.md`, report fields `references/report-template.md`, filled examples `assets/examples/`.
**Where things go**: run scripts by full path. Task outputs (jsonl, findings.json, reports) go in the **user's own working directory**. Newly measured official facts go into the **user's own notes** (e.g. `audits/references-local/<vendor>.md`), **not into the installed skill directory** (updates overwrite it) — unless the user is developing this skill.

## Rules (numbers are fixed for citation; grouped by phase)

Index: 1 quote first · 2 official baseline · 3 two reports · 4 no keys in repo · 5 only the tested field invalid · 6 conclusions follow evidence · 7 Seedance drafts · 8 latest generation only · 9 retest 503 / 429 · 10 measure missing baselines · 11 admin panels read-only · 12 "identical" must be computed · 13 everything to jsonl · 14 official side alongside · 15 three video checks · 16 Seedance veto · 17 stop on cross-tenant data

**Set up**
- **Rule 2 Official baseline**: use only official docs plus existing official measurements; ask the user before spending money on an official key. If the official key also serves other business, keep concurrency low and never put it in any report.
  **"Paid" means "may be charged", not "large request"**: completions, video generations and cloud-platform retests all count; `max_tokens: 0` or a huge max_tokens is charged as normal by some vendors (`kimi-k3.md`) — when unsure, treat it as paid. **The huge-`max_tokens` 400 that reveals the real model name is free only against the official Claude API**; through a relay treat it as possibly paid (pre-deduction, no refund, retries on other channels): send it once, read the supplier log `quota`, then decide whether to repeat. An "official account" handed over by the supplier is the thing under test, not a baseline.
- **Rule 10 Measure missing or stale baselines**: if an official baseline (`count_tokens`, `/v1/models`, prices) is missing from `references/` or is long past its `Last verified` date, fetch it with the official key and write it to the user's notes (`audits/references-local/<vendor>.md`) or the task directory; never leave "no baseline" in a report. **Free official calls (count_tokens, /v1/models, price endpoints) need no permission**; paid ones follow rule 2.
- **Rule 4 No keys in the repo**: scripts read keys only from environment variables. A version containing keys is made only on the user's request, with `secret` in the file name, added to `.gitignore`, local only.
- **Rule 17 Stop on cross-tenant data**: if a probe exposes another tenant's data (you can list someone else's tasks, read someone else's assets / draft records — see `seedance.md`), stop. Record only *that* it is possible and how many items, **read, download and store no content**, and report it to the user (in the external report it is a security issue the supplier must fix). Probes use only self-made text and the vendor's documentation sample assets — **never real customer data**.

**Free probes**
- **Rule 5 Make only the tested field invalid**: put the safety net on a field validated later; read code / docs to confirm the supplier will not fill in a default (wan3 without a resolution defaults to 1080P and really generates). An invalid probe value must be invalid for every model. Read actual spend before and after every paid or possibly paid action (prefer the supplier log quota, then the test token's used quota; billing/usage is reference only).
- **Rule 9 Retest 503 / 429 at least twice**: 3 attempts per (group, model), **classified by the body's `error.code`**: `model_not_found` "No available channel for model X under group Y" = usually a missing configuration; retest before concluding (the error often leaks internal group names; one case recovered on its own after 20 minutes, `new-api.md`). `unknown_error` / `get_channel_failed` / "upstream temporarily unavailable" = transient, often recovers. **Status codes are unreliable** (a missing channel shows as 503 on some sites and 429 on others; a dead upstream 502 may also be reported as 503). Report "transient, recovered" and "configuration missing" separately.
- **Rule 11 Admin panels read-only; never type passwords for the user**: to see the account pool / ratios, the user logs in in their own browser; the agent sends read-only GETs inside the user's logged-in session (endpoints in `sub2api.md`) and **takes only non-credential fields** (type / status / error / group / concurrency / rate-limit reason / ratio). Tokens, e-mails and uuids are not read, recorded or printed; no buttons that change anything; close the tab afterwards.

**Paid**
- **Rule 1 Quote before spending**: per-unit price, number of units and cap, then wait for the user's OK. **Test every tier; never extrapolate linearly; test tiers even if the price list shows them** (seen: 2K listed, money deducted, then "only 768P and below" and a refund; seen: cheap low tiers but 1080P close to the official price, so linear extrapolation underestimated several-fold). Estimate untested tiers at worst case ×8, go from the cheapest tier up, and look at the actual charge before the next tier.
- **Rule 7 Seedance: always test drafts**: if the supplier sells Seedance 2.5 (among the series currently on sale only 2.5 supports drafts; 1.5 Pro once had a 480p draft mode), include drafts in both free probes and the paid matrix and quote "draft 480p + final 1080p" separately; if it could not be tested, say why. Checklist: `references/seedance.md` "样片 draft 必测清单".
- **Rule 8 Latest generation only**: spend paid units on the newest version the supplier sells (newest flagship for text, newest image / video version); confirm with free probes that a newer version really is absent and write "no X" in the report. Older versions get free probes only, unless the user names them.
- **Rule 13 Every raw request / response goes to jsonl**: every free, paid and official request goes through `probe_lib.call()` / `call_stream()` into `artifacts/*.jsonl` (keys masked); no curl or ad-hoc scripts that don't log. Reports and appendices cite only jsonl (or artifacts generated from it), never hand-copied text.

**Verification**
- **Rule 12 "Identical" must be computed**: before writing "fields identical / same body structure", compute set differences of both sides' keys (top level, usage, response headers, SSE event names) in code — eyeballing easily misses extra supplier fields like `input_transformations` / `context_management`.
- **Rule 15 Three mandatory video checks**: ① is the output the official original (C2PA signer fingerprint / encoder / bucket); ② are drafts supported (rule 7); ③ are the returned link and parameters official or wrapped — the official video link, task id, resolution, duration and usage **may be renamed as long as the values survive**; **if everything is wrapped (the supplier's own link / handle, those fields gone), it cannot be integrated as the official API**. ③ goes into findings `passthrough` (the generator checks 5 core fields; if all are lost the internal card may not say primary / backup).
- **Rule 16 Seedance veto: no official original link or not an original → cannot integrate**. Both must pass:
  - ① Link: the returned link is a **raw direct link into the Volcengine Ark / BytePlus official bucket** (compare bucket names character by character, see `seedance.md`; renamed fields are fine, rehosting to the supplier's own bucket / VOD / CDN is not — `passthrough` status `rehosted`, counted as lost).
  - ② Original: `c2pa_check.py` reports "官方原片（指纹匹配）" (official original, fingerprint match: C2PA valid, hash matches, and the signing certificate fingerprint is in the known-official list `scripts/c2pa_known_signers.json`). If the list has no fingerprint for this vendor yet, compare against an original generated directly via the official API in the same audit. "Signature valid" alone is not enough: a self-signed certificate can claim to be any company.
  - If either fails → `internal.decision` is "不接" / `reject` (enforced by the generator; `meta.rule16: true` forces the gate on), and **stop testing**: check both on the first generated video and stop if they fail. Rule 15 ②③ and prices only matter once both pass.
  - This is a deliberately strict default; if your business accepts rehosting, change that check in the generator.
- **Rule 6 Conclusions follow evidence**; label inferences as inferences and undocumented observations as observations ("实测观察").

**Reports**
- **Rule 3 Two reports**, both generated by `scripts/build_report.py` from `findings.json`:
  - **External evidence report** (PDF, may go to business contacts / the supplier): only "this supplier vs official", no other third-party suppliers, no integrate / don't recommendation; claims vs measurements, authenticity evidence, list of differences (graded by customer impact), what the supplier must fix, appendix with raw requests / responses side by side.
  - **Internal decision card** (one A4 page, decision maker only): one-line verdict + recommendation (primary / backup / fix first / reject / pending) + **comparison with your existing lines for the same model** (cost, 30-day success rate; explain if none) + gateway readiness in three tiers + questions for the business side.
  - Stability / capacity are **not measured** (watch production monitoring after integrating), and the report does not say "to be tested". The 5 / 10-way concurrency in the matrices is a **protocol check only** (429 envelope, `retry-after` present or not, queueing vs rejecting, whether time-to-first-token degrades) — no capacity conclusions from it.
- **Rule 14 Official side alongside**: every raw request / response in the appendix has an official side (official measured jsonl first; otherwise an official documentation sample labelled `source: 文档示例`; if neither, a reason in `official.note`). The generator lays them out: side by side if both sides fit ≤ 66 characters per line and one page, otherwise stacked (official on top).

## Flow

0. **Set up**: in the user's working directory create a task directory (e.g. `audits/<YYYY-MM-DD>-<supplier>-<model>/`, with `artifacts/` for jsonl and outputs); keys / URLs in environment variables; read `references/<vendor>.md`, then `audits/references-local/<vendor>.md` from the user's notes (if present, the newer one wins).
1. **Free probes** (zero cost, all logged with `scripts/probe_lib.py`): does the official native path exist (an HTML page back = the official protocol is not implemented); identity and version (response headers), `/v1/models`, prices, submit / query routes, auth, error matrix (invalid params / missing headers / wrong key / nonexistent model / nonexistent task).
   Must read `references/probing-tips.md`: first make sure a CDN is not blocking your UA (1010); when the reason is wiped from the response, read the supplier log; **`billing/usage` is unreliable — actual spend comes from the log**; confirm the pricing tier each request actually landed in.
2. **Quote → minimal paid matrix** (rules 1 / 7 / 8): video per `video-checks.md`; text per the vendor reference's matrix — authenticity requests must be directly comparable with official ones.
3. **Verify**: video → output verification (C2PA fingerprint → ComfyUI → encoder / specs → link domain → eyes, `video-checks.md`); text → the four authenticity checks (id prefix, token-by-token count, model swap, injection, `text-checks.md`); then pick non-functional checks from `nonfunctional-checks.md` (output-token inflation, context truncation, output rewriting, data retention, compliance, region latency, refunds on failure), quoting first.
4. **Field-by-field comparison**: **baseline = the official docs of the vendor whose model name is sold**; if a capability fails and a cloud platform sits behind it, retest with that platform's own syntax first — only if the platform's official API also fails is it a platform limitation (`text-checks.md`). Three full request / response pairs side by side, field differences, error matrix with the same inputs on both sides; for text add a "docs / official measured / supplier" three-column table; non-functional findings go into `diffs` / `sections` / `internal.risks` per `nonfunctional-checks.md`.
5. **Cost**: supplier price ÷ official price per tier, billing moment, currency and exchange rate; check gateway readiness item by item against the vendor reference's "接入网关要求" (gateway requirements) and sort into three tiers (no code change / gateway change / supplier must add).
6. **Reports**: `python3 -I scripts/build_report.py --init video|text <task>/findings.json` for a skeleton → fill it (cite raw records as `{"jsonl","label"}`, never hand-copy) → `python3 -I scripts/build_report.py <task>/findings.json --pdf`. Validation blocks missing required fields / mandatory authenticity checks, internal line names leaking into the external report, and key-like strings. **Before sending, look at the page-break strips the generator produces** (a strip above and below each page break; full-page thumbnails hide split content). Audits of an official service itself (e.g. a newly opened official region) use the same flow against existing official baselines.
7. **Wrap up**: write newly measured official facts to the user's notes `audits/references-local/<vendor>.md` (with date and source; edit `references/` only when developing this skill); keep jsonl, findings.json and both outputs in the task directory.

## Scripts (scripts/)

| Script | Purpose |
|---|---|
| `build_report.py` | **Unified report generator**: `findings.json` → `artifacts/report.html` (external) + `internal-card.html` (internal); `--pdf` renders PDFs + page-break strips; `--check` validates only (also runs `--scan` for keys in artifacts); `--init` writes a skeleton; `--external-only` renders the external report only |
| `check_pages.py` | Strips above / below each PDF page break (called by `build_report.py --pdf`) |
| `probe_lib.py` | `call()` logs every request (including failed retries) to jsonl, keeps all response headers, masks secrets; `auth=` picks the auth style; official side via `side="official"` (env `OK` / `OB`); `call_stream()` raw SSE + time to first token; `spent(since_ts)` actual spend in USD from the supplier log; `vendor_log()`; `poll_task(preset=…)`; details in `probing-tips.md`, `python3 probe_lib.py` prints usage |
| `c2pa_check.py` | `--json`: C2PA manifest + signing-certificate SHA-256, compared with `c2pa_known_signers.json`, four verdicts: official original (fingerprint match) / signature valid but signer unverified / invalid signature or hash mismatch / no C2PA; `--trust-anchors <pem>` validates the chain |
| `analyze_videos.py` / `contact_sheet.py` / `extract_comfy.py` | Video specs and encoder / first-middle-last frames / ComfyUI workflow (usage in `video-checks.md`) |
| `html_to_pdf.sh` / `report_style.html` | Headless Chrome to A4 PDF / report styles (used by the generator) |

`assets/examples/{text,video}/` are fictional complete examples (findings.json + raw jsonl); run `--pdf` on one to see both outputs.
